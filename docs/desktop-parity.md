# Discord desktop behavior parity

Baseline: `MCShotty/NuSerein` main at `d63ec3b7`. Reference: public Discord desktop/browser guides and release notes linked below; the running official build was **not** observed. The installed-data path did not expose renderer source at the locations checked. No Discord profile data, credentials, client code, or assets were read or used. This is a working inventory, not a parity claim. The older [compatibility inventory](discord-compatibility.md#desktop-parity-inventory--october-17-2026) is useful background, not current build evidence. The [Signal Desk gallery](pr-evidence/signal-desk-full-pass/README.md) covers synthetic routes, not every interaction or official feature.

**Match** means the documented behavior is represented in source; it does not mean it was verified in a live Discord account. **Partial** means there is a native implementation with a known divergence or unverified interaction. **Missing** names an absent capability in the reviewed path. **Handoff** means the service or platform owns part of the flow. **Not observed** means evidence about the reference, eligibility, or behavior is insufficient. Record official build, platform, locale, entitlement and role when a comparison is available. The runtime protocol and live verification are separate from the UI disposition. Existing unofficial paths remain unofficial. Shop and Orbs, including links or prompts leading into either, are outside this project. Native Discovery and the in-game overlay are not part of the remaining implementation pass.

| Voice call while in a game → show/configure overlay | **Missing** — the [Game Overlay guide][overlay-ref] documents the official Windows overlay. Native app/game presence, the desktop call window and push-to-talk are not an in-game overlay. No game launch or injection was attempted. |
| Profile settings → owned cosmetics → choose scope, equip/remove, reset | **Partial** — shows only supported items Discord confirms the account owns. Reset choices is local. Losing server profile access hides that inventory without relabeling it as the global profile. A failed equip must be resolved or discarded before another change. No purchase prompt or Shop path. |
| Account settings → subscription status / management | **Partial / handoff** — the native account overview can show the service-reported tier; managing an existing subscription remains in the official client. No checkout, upgrade prompt or live entitlement verification. |

## Completion and verification gates

This source pass does not establish full desktop parity. In particular:

- **In-scope native gaps:** an embedded Activities catalog/host, reporting or managing spam-only DMs that are not confirmed pending requests, and service-backed entrance sounds and favorite sync. Discovery and the in-game overlay are excluded from this pass. Accept/Ignore for confirmed spam requests now have native controls but still require service verification. A detachable call window is not a game overlay.
- **Reference coverage still incomplete:** current desktop role/entitlement combinations, exact keyboard and recovery behavior, and the action-by-action settings and voice paths marked Partial or Not observed. Public help articles are evidence for the behaviors they describe, not a running-client comparison.
- **Overlay admission and verification:** the pinned viewport API can request topmost and pointer passthrough, but `RunningGame` describes presence, not the identity or bounds of the foreground window. The desktop renderer's `clear_color` also uses the root window's transparency policy for deferred windows. A non-injected overlay needs an explicitly admitted game window, isolated transparency and input behavior, and immediate retirement on focus loss, window replacement, disconnect or account change. Verify those against a synthetic foreground window first, then report windowed, borderless and exclusive fullscreen support separately. Do not enable it merely because a game name is present or count the call pop-out as that validation.
- **Hosted baseline:** run [45775058064](https://github.com/MCShotty/NuSerein/actions/runs/45775058064) passed Linux, macOS, Windows x64 and Windows ARM64 for the `78385f18` source tree. New changes require their own hosted evidence. Live checks require the separate owner-controlled developer-session gate.
